## AUDIO, formerly STORAGE (app 2.16; inside HOLODECK since 2.47)

- NAS: UGREEN DXP2800, UGOS Pro 1.18.1. Its own HTTPS cert is self-signed and its WebDAV refuses cross-site reads, so the app uses a **relay**: a `timothyos` Docker project with Tailscale (userspace, `TS_SERVE_CONFIG` proxies the ts.net HTTPS name to 127.0.0.1:8080) and Caddy (`file_server browse`, read-only `:ro` mounts under `/media`, CORS for `https://tim3t.github.io`, token as `Authorization: Bearer` or `?k=`). Compose is in the README; UGOS ignores compose `configs:`, so config travels in env vars written to files by the entrypoint/command. Tailscale on the NAS is on Timothy's own account, separate from the existing tailscale container that the NAS's administrator runs; leave that one alone.
- App: `LS_NAS` {url, token} typed in Systems (iPad only, like the access key; never in the repo, chat or tests). Listings: `fetch(dir/, Accept: application/json)`. Audio: one global `<audio id="nasAudio">` outside `#content` (keeps playing across screens) with `?k=` in its src. `NAS_HIDE` drops the alpine image's empty cdrom/floppy/usb folders at the root.
- Places: `LS_PLAYS` {path: {p, d, done, at}}, iPad only by Timothy's choice (he has no phone), pruned to 1,500. `markPlay()` is guarded by `pl.ready` (set after `loadedmetadata` seeks to the saved place) so a src change or a pause can't overwrite a resume point; MARK PLAYED clears `pl.ready` first for the same reason. Done = ended or within 30 s of the end.
- Art and tags (2.17): `nasList()` spots a picture in each folder (`COVER_NAME` first, else the first image) and stores `"f:" + path` in `LS_NASART`; the URL carries `?k=`. `readTags()` reads an MP3's ID3v2.3/2.4 with two ranged reads (header, then the tag, capped at 4 MB) and `parseId3()` takes TIT2/TPE1/TALB/APIC. Titles go to `LS_NASTAGS` (`dispName()`), artwork to `pl.artBig` (object URL) and a 240 px JPEG that becomes the folder art when it has no picture of its own. v2.2, whole-tag unsync and M4A fall back to filenames. Images use `.nas-img` over the initials; a broken one is removed by a capturing `error` listener. The mock relay builds its tagged MP3 and cover.png with ffmpeg.
- The pill (`miniPaint()`): full or minimized (`nasPref.mini`, remembered), ✕ sets `pl.closed` until the next play (any `play` event clears it). Body classes `nas-pad` / `nas-pad-min` add bottom padding to `.content`. Time-only updates touch just the time text (`data-sig`), so the buttons aren't rebuilt under a finger.
- TRACK # (2.18): `parseId3()` also takes TRCK/TPOS ("3/12" → 3). `scanFolder()` reads the first 64 KB of each untagged MP3 (four at a time, `nas.scan` progress), `saveTag()` marks read files with `s: 1`. Sorts are per folder in `LS_NASSORT`; `sorterFor()` is shared by browsing and CONTINUE LISTENING's up-next order. Tags past 64 KB (after a big APIC) fall back to the filename.
- Hidden folders: `LS_NASHIDE` (paths), filtered at render (`isHidden()`), unhidden in Systems. iPad only.
- AUDIO (standby) was folded into STORAGE (2.16), and STORAGE became HOLODECK's AUDIO program (2.47). Test: `app_e2e33` against `tests/mock_relay.py` (:8110).
- **Scrubbing** (2.51.3): iPadOS never focuses a touched range, so `paintPlayer(true)`'s `activeElement` check didn't protect a held slider and every `timeupdate` reset its value and clock (reproduced with CDP touch events in `app_e2e60`, also with focus refused as on the iPad). `pl.scrub` (`{id, v}`) is set on `pointerdown` and cleared on pointerup/cancel or touchend/cancel (a tick later, after the last `input`), which seeks with `scrubTo()`; while it's set the slider and its clock aren't repainted, `paintPlayer()` defers its redraw (`pl.scrubDraw`) and `render(true)` on the storage screen only refreshes the header. The CSS slider (`--fill`, 28 px thumb, `touch-action: none`) replaced `accent-color`. Live audio while dragging was considered and left out: each seek is a new Range request to the NAS.
- **STORAGE background play** (2.43.1): iPadOS suspends a home-screen web app in the background once it stops making sound, so a network load at a track's end could stall until Bridge was reopened. `preNext()` (from `timeupdate`) reads the next file into a blob in the last `PRE_SECS` (90 s, ≤ `PRE_MAX` 150 MB by Content-Length) as `pl.pre`; `timeupdate` hands off with `toNext()` at ≤ `PRE_HANDOFF` (0.4 s) left while still playing; `ended` stays the fallback. `playPath` uses the blob (`pl.blob`, revoked on the next change) or the relay URL; `preDrop` aborts and revokes. Gated by `autoNext()` (PLAY THE NEXT ONE on, sleep timer not at end of episode). Can't be reproduced in headless Chromium; e2e33 checks the read-ahead order and that no `ended` was waited on.

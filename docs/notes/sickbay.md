**Bridge 1.44.1 (app 2.76.1), from Timothy's first real shortcut build (2026-11-10).** Two faults found with a Quick Look of the combined text: date bubbles without *Include ISO 8601 Time* sent `2026-11-10`, which `new Date` read as UTC midnight (every day one day early in the Americas), and a Find with Limit on applied the limit *before* Group By (three newest samples summed into one "day"). `healthWhen_` now reads a bare `yyyy-MM-dd` as noon UTC (the same calendar day from UTC-11 to UTC+11). In `healthPut_`, any day on or before `edge` (now minus 3 days in the script zone: "in the last 3 days" counts back from the run, so that day is partial) merges with the page's values winning, and is skipped when it adds nothing; newer days still overwrite field by field. README's guide was rewritten from the build that worked (drag fresh actions so Repeat and Add to Variable pick up the action above; Sort None, Limit off; Quick Look check; Time of Day automations with Auto-Lock Never).

**Bridge 1.45 (app 2.78): check mode and reasons.** `healthDays_(raw, tz, notes)` fills `notes` with a row per non-empty line: `{n, code, read, day, bare}` when used, `{n, code, why}` when left out (`HEALTH_WHY`: no_date, backwards, repeat, stage, code, number, range; `healthPut_` adds old, future, many for lines whose day falls outside the 14-day window or past the 10-day cap). `bare` marks a date with no time. With `body.check` (true or yes/true/1) `healthPut_` returns after parsing, before the lock and any Notion call: a one-line `message` (what was read per code, the day span, left-out lines grouped by reason, the no-time warning) and `lines` (first 80). A real send's message now carries the same reasons and warning. Check mode needs HEALTH_KEY like any send. Tests: bridge_sickbay (nothing written in check mode; the exact message and lines).

**DAYS and arrival (app 2.80, bridge 1.47, D78; Timothy approved a mockup with invented data, 2026-11-12, weight removed from the day).** Bridge `healthPut_` stamps a day's Data JSON: `_got` (ISO, when its page was created), `_upd` and `_add` (when a send added measures it lacked, and which; a value merely replaced is not an addition). App: `skStatus(date, exp)` gives arrived / partial (missing some of `skExpected()`, the daily measures present on at least half of the last 14 days with data, so measures the shortcut doesn't send never make every day partial; today is always partial) / waiting (no data, 0 or 1 days old, or nothing later either) / missing (later days came). `skArriveHtml` is the banner on every tab. VITALS: readiness label names the latest night; ACTIVITY is seven `skRing` SVGs (MOVE `--chrome-d`, EXERCISE `--hero`, STAND `--work`, dashed when absent) and GOALS (`skView().goals`, default 500/30/12, in tos.sickview.v1 so profile sync and backups carry it); tiles use `skLatest(k, 30)` and the day (`skTileWhen`), no sparklines; the detail chart is 7/14/30 days (old 90 maps to 30), bars are buttons (`data-skbar`, `sk.bar`) with a tip and OPEN THE DAY; the 30-day average line is gone. DAYS: `skDaysHtml` strip (`data-skday`), day card (`sk.day`, default the newest arrived day; `data-skstep` back to the oldest loaded day, never past today), stamp lines, rings, the night (segments if sent), and six measures (no weight: Timothy records it in RECORDS); cardio fitness absent says NOT MEASURED with the latest. SLEEP's aside has OPEN THE DAY. Test: e84 (mock_sickbay: day 8 missing, yesterday without movement, stamps on days 0 to 13, cardio fitness every 4th day).

**2.81.2 (Timothy's real Thursday, 2026-11-13: ARRIVED with steps short of Health).** `skStatus` used to call a past day ARRIVED once every expected measure was there; by mid-afternoon they all are. Now ARRIVED also needs a send after the day ended: the latest of `sk.data.last`, the day's `_got` and `_upd` must fall on a later date, else `{s: "partial", early: last}` and the day says "Last sent at HH:MM on the day itself". (The bridge stamps `_upd` only when a measure is added, not when a value grows, so the overall last send is the better signal.) `SK_LATE_MS` (14 h): `skArriveHtml` turns into NO SEND SINCE with SYNC FROM HEALTH (`.sk-late`). The bridge already overwrites the last 3 days on each send (only the oldest day of the window is fill-only), so the next send trues the day up. mock_sickbay `skmode&early=1`; test e90.

**2.80.1 / bridge 1.47.1 (Timothy's first real data in DAYS, 2026-11-12).** `skFirst()` is the first day with any data; a day with none before it is `before` (dim chip `.sk-dbefore`, key item, pill, its own card), never `missing`, and the banner skips it. Stand: Apple's ring counts hours with a minute of standing; Timothy's Shortcuts offers only Stand Minutes, which he now groups by Hour. `healthDays_` reads a `standmin` line spanning at most 61 minutes as one hour (`_standhrs[HH]`, counted when the value is above 0; 0 to 60 accepted) and sets `stand` to the number of hours; a whole-day line is still minutes ÷ 60.

## Stations, Habits, Library

**Stations** (app 2.7): the bar is `#pins` (rendered by `renderNav()` from `pins()`: `tos.pins.v1` on the iPad, max 7, default TODAY WEEK LOOM REVIEW LOG HABITS LIBRARY) plus `#allBtn` (ALL STATIONS, where the empty `.fill` block was) and `#status`. `STATIONS` lists every screen with its group; `openLaunch()` shows `#launch` over `#content` (same grid cell); EDIT PINS (`state.pinEdit`) changes `tos.pins.v1`. Tests that click MONTH, DATES or LEDGER in the bar set the pre-2.7 pins with `addInitScript`. Never reuse the class `.standby` (it's the screensaver): launcher tiles use `.st-off`.

**Habits** (bridge 1.14, Notion `NOTION_HABITS_DATABASE`, one page per day: Meditated, Evening Walk checkboxes, `Water (L)` number in 0.5 steps, `Debit Card` select Did Not Swipe / Swiped). Actions: GET `habits` `from` `to` (≤ 400 days, cached 2 min, generation `hgen` bumped by writes), POST `habitset` `day{date,med,walk,water,card: kept|swiped|null}` (whole day, upsert on Date). App: `hb` state, `tos.habits.v1` (370 days), `tos.habitq.v1` (unsaved days; `setHabit()` → 700 ms → `flushHabits()`, retried on refresh, online and every 30 s after a failure), water goal `tos.habitcfg.v1`. `hWin()` decides a won day (water ≥ goal; card kept); the Bridge's WATER chip short of the goal is tinted `color-mix(--work 10% to 50%, transparent)` by progress (2.75; 50% keeps light text readable); a day with no page is "not recorded", never a miss. Review rollup (`habitsWeek()`, `habitsTrend()`) is computed from the Habits database, not stored in Weekly Reviews.

**Growing text boxes** (2.26.1): `growBox(ta)` sizes any textarea except `.cl-text` (the Log has `growLog`) to its text, honouring a CSS `max-height` (then `overflow-y: auto`; Ask's `#askText` is capped at 40vh) and keeping ancestors' scroll positions. Runs on `input` (capture), after DOM changes (a body `MutationObserver` on childList and `hidden`, one pass per frame via `growAll()`), and on width change. New textareas need nothing extra. Test: `app_e2e38`.

**Tarot** (app 2.26, bridge 1.24; Notion `NOTION_TAROT_DATABASE` 🔮 Tarot, created by Claude with Timothy's go-ahead: Title, Date, Kind Reading / Meaning / Spread, Weekly checkbox, Spread, Cards (readable), Interpretation, Card (code for a Meaning), Data (JSON: spread, q, pos, cards, notes; `rtLong_` up to 40 × 2000 chars)). Card codes: `M0`–`M21`, `W|C|S|P` + 1–14. Actions: GET `tarot` `from` `to` (≤ 400 days; readings in range plus every Meaning and Spread; cached 2 min, `tgen`), POST `tarotsave` `reading{cid | id, day, spread, sname, q, pos[{l,x,y,c}], cards[{id,rev}], notes, sum, weekly}` (whole reading; weekly needs one card and unmarks any other weekly card in that Monday-to-Sunday week), `tarotmeaning` `card, text` (one page per card; empty → trash), `tarotspread` `spread{nm, pos}`, `tarotremove` `id` (reading or spread → trash; page must be in Tarot). App: `tr` state; `tos.tarot.v1` (13 weeks), writes queue in `tos.tarotq.v1` (keys `r:<id|cid:…>`, `m:<card>`, `s:tmp:…`, `x:<id>`; `flushTarot()` one at a time, retried every 30 s; a pending reading shows from the queue and its later edits are re-pointed to the real id when it lands), unsaved new reading `tos.tarotdraft.v1`, Ask switch `tos.aitarot.v1` → `tarotBrief()` (≤ 4000 chars). `askReshare()` clears Ask's snapshot when finances or tarot sharing changes. Bridge panel `tarotPanel()`, Review `tarotWeek(w0)`, Systems `tarotSection()`. CSS classes all start `tr-`; cards are drawn, no deck art; size with container units (`cqw`) on elements *inside* the card: `cqw` on the card itself measures the container around it, not the card (2.29.2 bug: empty position labels sized to the screen; text goes in `.lab`). Faces (2.27, agreed with Timothy on a design sheet): `trArt(id)`: Majors from `TR_MAJOR_ART` (22 marks in a 40×40 box, stroke 2.4; the Fool is a flower, Death a scythe); Minors from `trSuitArt(suit, strokeWidth)`: Ace one mark, Two to Ten `TR_PIPS` (40×60, `.pip` groups), courts `TR_COURT` sign above the mark (`svg.court`). Tests: `bridge_tarot.test.js`, `mock_v24.py` (:8105) + `app_e2e38`.

**Tarot books** (app 2.29, bridge 1.25; Notion `NOTION_TAROT_BOOKS_DATABASE` 📖 Tarot Books (id in CONFIG), created by Claude with Timothy's go-ahead: Title "The Chariot · Liz Dean", Card (code), Book select `Liz Dean` / `Jessa Crispin`, Source (chapter, page), Order (deck position × 2, Crispin +1)). The page body is the passage: `heading_3` per section, paragraphs, bulleted items (`• ` in the app). The import file (JSON `{v, books, cards[{code, book, source, sections[{h, p[]}]}]}`, private, never in the repo) is a file block on a page with no Card; `tarotbookimport` makes the missing pages (≈50 s per call, `left` says how many remain; never overwrites). Dean's sections: AT A GLANCE (facts as bullets), UNDERSTANDING, ASTROLOGY, KABBALA (Majors), UPRIGHT MEANING, REVERSED MEANING, WISDOM MESSAGE, SYMBOLS, REFLECTIONS; "TRY A READING" exercises were left out. Crispin's: THE CARD (her description), HER READING, RECOMMENDED MATERIALS, and for Minors FROM HER CHAPTER ON THE ACES… (rank introduction plus her one line for the card); her Coins are Pentacles (`P`). Actions: GET `tarotbooks` (counts per book, `file`, `url`; cached 10 min, `tbgen`), `tarotbook` `card` `fresh` (both books' sections, Dean first; 6 h cache; children read with `fetchAll`), POST `tarotbookimport`, `tarotsuggest` `{mode card|reading, at, cards[{id, rev, pos, note, mine}], q, sname, sum}` (Sonnet 5.5 low effort, `TAROT_SUGGEST_RULES`, no tools; a card sends its whole passage, a reading the core of each: key meanings, upright or reversed, wisdom, Crispin's card and reading; spend counted, log mode `tarot`; nothing saved). Caps `tarotbooks` (Notion) and `tarotsuggest` (Notion + Anthropic key). App: `trb` state (memory only), boxes by key `p:i` / `s` / `h:CARD` redrawn in place by `trbPaint()`, `trbSystemsRow()` in `tarotSection()`, IMPORT loops `tarotbookimport` until `left` is 0. Tests: `bridge_tarotbooks.test.js`, `mock_v24.py` `tbmode` (placeholder passages) + `app_e2e39`.

**Apiary** (app 2.31, bridge 1.26; Notion `NOTION_APIARY_DATABASE` 🐝 Apiary (id in CONFIG), created by Claude with Timothy's go-ahead and seeded from his earlier hive log page, which stays as it was: Name, Kind Yard / Hive / Check, Date, Who, Queen, Frames, Stores, Feed, Temperament, Pests, Did, Issue, Next, Notes, Mites (%), Honey (lb), Data, Hive (relation to the hive page, two-way with Checks)). Data is JSON, read from its first `{` (`apiaryData_`; the Notion tool rejects a value that starts with `{`, so the seeded rows begin "TimothyOS {"): a hive's `{order, paint, paint2, trued (ymd of the last TRUE UP), boxes[] top to bottom, about{source, foundation, equipment, place}}`; a box (2.32, bridge 1.28 `APIARY_PIECES`) is `{k: deep|medium|super, n frames (6..12; app defaults deep 10, medium 10, super 9), drawn 0..n (filled, for a super), fill 0..1 capped (medium, super)}`, `{k: feeder, level EMPTY|LOW|FULL}` or `{k: excluder}`, null = not counted, a check's `{deeps[bottom first], picks{…}}`, the yard's `{facing, list[{t, done}]}`. Actions: GET `apiary` (yard, hives by Data.order, checks newest first; cached 2 min, `agen`), POST `apiarysave` `item{kind, cid | id, name, day, who…notes, mites, honey, data, hive (check), boxes (check: also written into the hive's Data)}` (whole record; check title = hive name · date; one yard only), `apiaryremove` `id` (check or hive to trash, never the yard). App: `ap` state, `tos.apiary.v1`, queue `tos.apiaryq.v1` (keys `y`, `h:<id|cid:…>`, `c:<id|cid:…>`, `x:<id>`; `flushApiary()` one at a time, oldest first so a new hive lands before its check; `cid:` ids aliased in `ap.alias` and rewritten in waiting items), draft `tos.apdraft.v1`, Ask switch `tos.aiapiary.v1` → `apiaryBrief()` (≤ 4000 chars, `CLAUDE_DROP` "apiary" first). Views `ap.view` yard / hive / check / new / checkedit / hiveedit / stackedit (TRUE UP STACK, `ap.tu` {hive, boxes, orig, sel, log, day}: `apInsert()` puts a piece by `AP_PIECES[k].rank` on top of its own kind; SAVE queues the hive (data.boxes, trued) then, with LOG THIS TOO, a check whose did is `apTuSummary()` + " (logged later)" and no boxes); a check's per-box marks `draft.counted` (drawn) and `draft.capd` (fill) follow inserts and removals through `apShiftKeys()`; `apNav(view, stackEl)` re-renders and flies a clone of the tapped stack (`.ap-ghost`) to the new one (`data-apstack`), plus `.zin`/`.zout`; never on background renders, off with Reduce Motion. `apStack(h, u, pick)` draws a stack at unit `u` px. A new check counts only boxes touched (`draft.counted`); `apSaveDraft()` writes the picks as sentences and REMIND adds a task via `addtask` (Life Area: first containing "bee", else one `taskArea()` maps to farm). Hive weather from `hiveCheck()`. Class names all start `ap-`. Hive and queen names are Timothy's: never in the repo or tests (mock_v24 uses invented ones). Tests: `bridge_apiary.test.js`, `mock_v24.py` `apmode` + `app_e2e44`.

**Library** (Notion `NOTION_LIBRARY_DATABASE`: Title, Author, Status Want to Read / Reading / Read / Set Aside, Started, Finished, Rating 1 to 5, Notes, Cover url, Open Library url, Published). Actions: GET `library` (cached 5 min, `lgen`), POST `booksave` `book{cid | id, …}` (only fields sent are written; cover must be covers.openlibrary.org, link openlibrary.org; page must belong to the Library), POST `bookremove` `id` (to Notion's trash). App: `lb` state, `tos.library.v1`, optimistic changes put back on failure; Open Library search runs in the browser (`olSearch()`, 450 ms debounce). Tests: `bridge_habits.test.js`, `mock_v21.py` (:8102) + `app_e2e24`.

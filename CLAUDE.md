# TimothyOS: working notes for Claude

Personal, LCARS-inspired life dashboard for Timothy, installed as a home-screen web app on his iPad. Since 2.34 the app is named **Bridge** (home-screen name, `<title>`, manifest); **TimothyOS** is the system it runs and stays in the top bar, the repo, storage keys (`tos.*`), the Notion integration name and backup file names. Single user. He works mostly from the iPad (Safari, a-Shell), not a computer.

Read `docs/DESIGN.md` (decisions D1 to D47; its sections 1 to 13 are the original plan, kept as history) and `CHANGELOG.md` before changing anything. `README.md` is Timothy's setup and daily-use guide: keep it accurate whenever behavior or setup changes.

## Architecture

```

  ▼
```

Key refusals are distinct: `no_key` (request arrived without its details; a POST can become an empty GET on a Google redirect), `key_unreadable` (settings store answered empty), `unauthorized` (wrong key). The app's `transient()` retries the first two. Log reads go as GET via `logRead()` (falls back to POST on `unknown_action`). The written-days list is cached 6 h under `logdates` and updated in place by `logDatesAdd_()`; setup clears it.

Batched reads: `api()` holds batchable reads for 40 ms and sends them as GET `batch` (`calls` = JSON list, ≤ 8) when more than one is waiting; the bridge's `batch_()` runs each through `read_()` and returns `results[]`, each with its own ok/error. Falls back to single requests on `unknown_action`. `netPending` counts requests in flight (REFRESH NOW's spinner); `markRetried()` flags netlog entries for attempts `withRetry()` tried again.

Capabilities drive the UI (`capabilities_()`): always `read`, `create`, `holidays`; with `NOTION_TOKEN`: `tasks`, `dates`, `done`, `reviews`, `reviewlog`, `queue`, `log`, `habits`, `library`, `tarot`, `tarotbooks`, `apiary`; `logpin` once `LOG_PIN` is set and `logcode` when it is a code word (has a `-`); `logsearch` once `LOG_SEARCH_READY`; `ask` and `brief` (1.29) with `ANTHROPIC_API_KEY`; `logask` and `tarotsuggest` with both the Claude and Notion keys; `ledger` with `YNAB_TOKEN`; `voice` with `OPENAI_API_KEY` (1.30); `schema` with `NOTION_TOKEN` (1.31). Every write is idempotent (cid cache for 6 h, or set-to-value), so retries are safe.

## Rules

- **Secrets never go in code, chat, commits or notes:** `ACCESS_KEY`, `NOTION_TOKEN`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `YNAB_TOKEN`, `LOG_PIN`. They live only in the bridge's Script Properties (and the access key in the iPad app). The NAS relay token, the Home Assistant token and the Tailscale auth key live only on the iPad (and in backups) or the NAS; the tailnet name and real NAS paths stay out of the repo. The repo is public.
- **Tarot books are copyrighted.** Passages from Timothy's two tarot books (Dean, Crispin) live only in his private 📖 Tarot Books database. Never put book text in this repo, tests, mocks, commits, published pages or artifacts; use placeholder text. The app keeps passages in memory only (never localStorage).
- **Privacy:** the Life Hub holds private pages. Never open or read them without Timothy's explicit permission, and never put real personal data (task or date titles, Life Area names, people) in this public repo, including tests. The Notion integration is connected only to Master Task List, Key Dates, Weekly Reviews, Replicator Queue, Captain's Log, Habits, Library, 🔮 Tarot, 📖 Tarot Books and 🐝 Apiary (Timothy connects each one himself); keep it that way. When reading the workspace to plan, read structure (schemas), not content.
- **Work calendar is read-only forever.** Don't add write paths for it.
- **Farm calendar** (bridge 1.8): area `farm`, ID only in Script Property `FARM_CALENDAR_ID` (never in code: its name is personal). `sources_()` leaves it out until set. The app's `setAreas()` moves `farm` from STANDBY_AREAS to LIVE when the bridge lists it, labels it with the calendar's name, and adds it to Capture's `WRITABLE`. Tests: `mock_v18.py` + `app_e2e19`.
- **Don't change Notion schemas or create databases** without asking first.
- UI copy and docs: **no em dashes**. **No emoji in the interface** (they clash with LCARS): show Notion labels through `bare()`, keep the raw value for writes. Flat marks (◆ ▲ ▼ ✕ ✓) are fine; ☀ ▶ ◀ ❄ are not (iPadOS draws them as emoji). `app_e2e13` checks this. Uppercase display labels use the Antonio font; keep the LCARS frame (elbow, chrome colors, area colors as tokens in `css/app.css`).
- **Mockups:** when Timothy asks for a mockup, publish it straight away as a private Artifact link he can open in Safari (his standing instruction, 2026-10-23; no need to ask first). Invented data only, as in tests.
- Big touch targets (≥ 48 px), works offline, fits iPad landscape (1180×820 and 1133×744) and phone width (400 px, no horizontal scroll).

## Captain's Log

## Known quirks (already handled; don't "fix" them away)

- **No zoom, ever (2.7.2):** Safari zoomed the whole app on a quick double tap (a PIN with a repeated digit). `touch-action: manipulation` on html, body and controls turns double-tap zoom off without delaying taps; `gesturestart` and two-finger `touchmove` are cancelled; the viewport has `maximum-scale=1`. Don't add a "double-tap guard" that swallows the second touchend: it would drop the repeated digit. `app_e2e22` checks all of it.
- **Google's result page intermittently 404s** (about 1 in 8 requests) even though the script ran. `withRetry()` re-runs the request twice for `http_404`, `bad_json`, `http_5xx`. Re-fetching the same result URL does not help.
- **Dropped and background-cut requests:** iPadOS kills in-flight fetches when the app is backgrounded or the screen locks. `withRetry()` waits for `visibilitychange` and re-runs those, and retries `TypeError` drops (3 times). `slot()` caps bridge requests at 2 in parallel. A refresh failure over saved data shows `retrying`, not `offline`, until 3 in a row. `netlog` (Systems → Recent requests) records action, duration and outcome only, never data. `app_e2e14` covers this.
- **Lost replies:** a write can succeed while the reply is lost. `reconcileQueue()` clears queued items that already appear in loaded data, so they're never re-sent after the 6 h cid cache expires.
- iOS standalone apps don't reload on resume. `version.json` + the **UPDATE READY** banner handle updates; the service worker fetches the page with `cache: "no-cache"`.
- The app draws under the iPad status bar (`black-translucent`, `viewport-fit=cover`). Top clearance is `--safe-top` + `--top-gap` (fixed at 30 px since 2.7.3; the Systems setting was retired), with a solid `body::before` strip behind the bar. Overlays (`.scrim`) follow the visual viewport (`--vv-top`, `--vv-h` from `fitViewport()`) and pad by the same clearance, so ASK and CAPTURE stay below the status bar and above the keyboard. Don't switch the status-bar style meta: iOS reads it only at install, so Timothy would have to re-add the app and re-link.
- Plain GET and text/plain POST only, no custom headers: Apps Script can't answer CORS preflights.
- Calendar toggles (Work/Personal hidden) persist in localStorage and affect Day, Week, Month.
- **Water goal history** (2.30): `tos.habitcfg.v1` = `{goal, hist:[{from, goal}]}` (oldest first; first `from` is ""). `waterGoal(key)` is that day's goal, `waterGoal()` today's; `hWin(id, d, key)` must get the day's key. `setWaterGoal()` replaces a same-day change and drops a no-op.
- **OPEN IN CLAUDE** (2.30.2): `claudePrompt(q)` = question first, then `briefing(true)` sections (`{t, k}`; `k` names a section that may be left out). Link text ≤ `CLAUDE_LINK_MAX` (6000, chars before URL encoding): whole sections dropped in `CLAUDE_DROP` order, marker on top, "(Left out to fit: …)" at the end; hard cut only if still too long. Clipboard = full prompt, no marker. `briefing()` (no argument) is unchanged for ASK (snapshot ≤ 40,000 at the bridge). The Ask box caps a question at 2,000 characters. `app_e2e43`.
- **ID3 reading** (2.30.1): `id3Head`/`id3Walk` handle v2.2 (3-letter ids, `ID3_V22`), v2.3 and v2.4 (syncsafe frame sizes, per-frame unsync, data-length indicator, grouping), whole-tag unsync (v2.2/2.3, `deUnsync`). `scanTags(it)` (TRACK #) walks from a 64 KB read and, when a frame crosses the end (a big APIC first), reads on from the next frame (≤ 6 hops) instead of the 4 MB tag; falls back to ID3v1.1 (last 128 bytes). `nasTags` entries carry `m`/`z` (file mod time, size): `scanFolder` re-reads when they differ or are missing (entries from before 2.30.1). `data-nas="rescan"` clears `s` for the folder. Relay mock `/Podcasts/Show C` has one hand-written tag per layout; `app_e2e42`.
- **Track lengths** (2.30): `lenScan(dir)` on opening a folder, two files at a time, ranged reads only: `mp3Len` (Xing/Info/VBRI, else ID3 TLEN, else CBR from size; a second read past a big tag), `mp4LenRead` (mvhd, hopping over mdat), FLAC STREAMINFO, WAV fmt/data. `tos.naslen.v1` `{path: {s, z}}` keyed by size; `s: -1` = unreadable, not asked again. Rows show `lenOf(it)` (player's measured length first), documents their size. Relay mock makes the samples with ffmpeg (`/Music/Lengths`) and counts bytes served (`STATS.sent`); `app_e2e41`.
- **Text fields need a stable id.** `render()` keeps the focused field, its caret and any typed text by element id; a field without one loses the keyboard on every background redraw (2.29.1 fix for tarot notes). Ids must not change while you type (a new reading's notes use `trUk()`, shared by its `cid:` and Notion ids) and must differ between records (else typed text is restored into another record's box). `app_e2e40` fails on any `<textarea>`/text `<input>` in app.js without `id=`. Tarot typing lives in `tr.dirty` (and `tr.mdirty` for meanings) and is drawn over Notion's copy until queued; `tr.alias` follows `cid:` to the real id.
- **Never hold `LockService.getScriptLock()` for long work.** It's one lock for the whole script: anything else waits up to 15 s and throws "Lock timeout". Long jobs use a cache flag (`tbimporting`); lock timeouts map to `error: 'busy'` (`lockBusy_`), which the app treats as transient.
- **Ignored events** (`tos.ignore.v1`, title phrases, case-insensitive contains) are filtered inside `eventsFor()`, so every view and total skips them. Raw `state.ranges` stay unfiltered (reconcile needs them). The list is device-only: Timothy's real titles never go in the repo. `app_e2e15` covers it.

## Testing

`tests/run.sh` runs the bridge against simulated Google, Notion, YNAB and Claude services (Node `vm`), then drives the real app in headless Chromium (Playwright) against simulated bridges `mock_v10` to `mock_v24` and the relay `mock_relay.py`, in America/Chicago time (deliberately not Timothy's Eastern time, so time-zone bugs show up). Most browser tests fix the clock (`page.clock.setFixedTime`, mostly 6 Oct 2026); about a dozen newer ones (e2e27, 32 to 35, 38 to 45) and some bridge tests run on the real date, so give any new date-dependent test a fixed clock, or it can pass one day and fail the next. The app itself always uses the iPad's own time zone. Screenshots go to `tests/out/`. Real Google/Notion can't be tested here (no keys, by design); Timothy's first real run is the live check, so give him a concrete thing to verify.

**Lanes (2026-10-22):** the browser tests run in `LANES` (in `run.sh`), up to `JOBS` (default 3) side by side, longest first; about 5 minutes instead of 12. The simulated bridges keep state between tests (saves, counters, switched modes), so every test that touches a given mock port runs in the same lane, in the original order; lanes share nothing but the static page server. The relay is the one mock several lanes need, so each such lane gets its own (`mock_relay.py <port>`, `RELAY_PORT` 8110 / 8111 / 8112; tests read `process.env.RELAY_PORT`, default 8110). `app_e2e21` samples the standby fade frame by frame and runs alone after the lanes. A new browser test goes into the lane of the mock it uses (or a new lane if its mock is unused); never let two lanes use one mock port. `JOBS=1` runs lanes one at a time (also automatic on bash before 4.3). Each result line shows its seconds. Never end the lane wait with a bare `wait`: the servers are children too and never exit (it hung once).

Limit: the runner fails on crashes, page errors and timeouts, but most tests print their key values (event counts, toasts, saved items) instead of asserting them. Run `VERBOSE=1 tests/run.sh` and read the output after any change, and convert printed checks to `assert` calls when touching a test.
